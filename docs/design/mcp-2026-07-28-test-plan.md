## How a case is driven

Stdio spawns `nab-mcp` with no arguments. The default transport is stdio (`main.rs` lines 1184–1189). One JSON object is one line. The client reads one response, or it reaches the read budget that case names. The budget for a local JSON-RPC response, for silence, and for a refusal that must not wait is 2 seconds. A local response arrives well under that. Zero bytes while the process is still running, inside that budget, is silence. A crash is a harness failure, not a pass, and not the assertion under test.

A case that performs network I/O, transcription, or a 1Password CLI lookup names its own budget. Each of these is a harness bound, not a product constant. The local-listener budget is 60 seconds. It covers TP-C4, TP-C5, TP-C6, the served `task` calls in TP-TASK-2, and the `fetch_batch` half of TP-NOTASK-1. The listener is on the runner, so a correct return finishes well under that. TP-C7 awaits remote fetches that have no deadline of their own (`helpers.rs` lines 286–303). Its budget is 3 minutes. The transcription budget is 10 minutes. It covers every TP-AN-2 call, including the refusal, because `transcribe` runs before `apply_active_reading` (`analyze.rs` lines 171–202). The record caps the audio at 60 seconds. The vault budget is 60 seconds. It covers the three 2026 refusals in TP-LOGIN-3 and the three 2025 vault sends in TP-LOGIN-4. Each of those calls runs `op account list`, then `op item list`, then `op item get` for every match, before the call can refuse or elicit (`auth/mod.rs` lines 126–130 and 179–226, `login.rs` lines 87–113). The served call in TP-LOGIN-3 does that lookup and then awaits `login_flow.login` (`login.rs` lines 153–156). Its budget is 3 minutes. OAuth returns before any `op` command (`login.rs` lines 66–85), and the unavailable branch runs only `op account list` with the binary absent, so TP-LOGIN-1 and TP-LOGIN-2 stay on the 2 second budget. The watch notification bound stays 75 seconds, measured from the body change. The 2 second budget is not applied to the cases that name one of these longer bounds. A server that waits past the budget that applies to the case fails the case.

HTTP spawns `nab-mcp --http 127.0.0.1:<free port>`. Every request uses the path `/mcp`. That is `DEFAULT_STREAMABLE_HTTP_ENDPOINT` (`http_utils.rs` line 35). Nab does not set `custom_streamable_http_endpoint`. A request to `/` is a harness failure. Unless a case says otherwise, the request carries `Origin: http://127.0.0.1`, `Host` set to that bound address, `Content-Type: application/json`, and `Accept: application/json, text/event-stream`. Those headers keep the DNS-rebinding middleware and the 0.9 accept check from deciding the case (`dns_rebind_protector.rs` lines 112–114; `mcp_http_handler.rs` lines 342–346). A 403 means the harness sent the wrong origin. That is a harness failure, not a protocol result.

The JSON value a case reads depends on the response `Content-Type`. A type that starts with `application/json` means the body is that JSON value. Produce-400 rows and other `error_response` bodies are this form (`http_utils.rs` line 680). A type that starts with `text/event-stream` means the JSON-RPC object is the `data` of the first SSE event whose data is non-empty. The event bytes are `data: `, then that JSON, then a blank line (`sse_event.rs` lines 87–101). An empty line, and a line that is only `:`, are keep-alives (`http_utils.rs` lines 591–593). They are not the message. `start_new_session` and a session POST use this stream (`http_utils.rs` lines 394–401, `mcp_http_handler.rs` lines 367–374). Nab leaves `enable_json_response` unset, and the default is false (`hyper_servers/server.rs` line 334, `main.rs` lines 1399–1410). A `JsonRpc` answer is HTTP 200 and its body carries the JSON-RPC object. The design does not name a `Content-Type` for that answer. The harness accepts `application/json` whose body is the object, and it accepts `text/event-stream` whose first non-empty `data` is the object. Parsing an SSE body as raw JSON is a harness failure. The case does not pin which of those two framings the patch writes.

Every spawned server gets an empty `HOME` and an empty `XDG_DATA_HOME`. Watch files live under the XDG data directory (`src/watch/mod.rs` lines 73–81). A developer machine with saved watches would make the empty-store literal fail for the wrong reason.

The selecting field is `_meta["io.modelcontextprotocol/protocolVersion"]`. The capabilities key is `_meta["io.modelcontextprotocol/clientCapabilities"]`. The header name is `mcp-protocol-version`. The session header is `mcp-session-id`. An empty header value is the absent header (`http_utils.rs` lines 637–639).

A JSON-RPC success has `jsonrpc` equal to `2.0`, `id` equal to the id that was sent, a `result` object, and no `error` key. A JSON-RPC error has `jsonrpc` equal to `2.0`, the same `id`, an `error` object, and no `result` key. The id used below is the integer `7614`, except one case that sends the string `req-7614` to prove the echo is not a hardcoded number. Refusal code is the integer `-32600`. Method-not-found is the integer `-32601`.

An HTTP 400 SdkError body has exactly the keys `code`, `data`, and `message`. `code` is `-32015`. `data` is null. There is no `jsonrpc` key. The message text of a callback-produced 400 is not pinned. The design requires the SdkError object and does not choose the words. Two callback rows that share status, code, and key set are not separated by the message.

A tool error from `run` is a JSON-RPC success whose `result` is the tool error this server already returns. It is not `error.code` `-32600`. The sampling refusal and the elicitation refusal are `-32600`.

The client records every message that arrives before the response. A case that names a drain after the response keeps reading for that drain. A message that arrives only after the response still counts for that drain. A refusal is one JSON-RPC message, and that message is the error. It is not `elicitation/create` and it is not `sampling/createMessage`. The client does not answer a server request. A server that waits past the budget named for that case fails the case.

| A3 | A set case names the members that arrived. An empty list fails. |

| A6 | No absolute timestamp. The 2 second budget, the 60 second local-listener budget, the 60 second vault budget, the 3 minute remote budget, the 10 minute transcription budget, and the 75 second watch bound are harness bounds, not product constants. |
