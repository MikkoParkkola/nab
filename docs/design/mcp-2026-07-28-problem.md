# Problem definition — MIK-7614

Status: awaiting ratification. Thirteenth statement of the problem. This document chooses no solution and no SDK.

## Problem

A client that sends MCP revision 2026-07-28 does not get that revision from nab. On the revision this problem accepts, that client's request stands alone: no `initialize` and no session id. A `tools/call` succeeds for every tool whose call can finish without asking the client a question. `watch_list` is the offline proof of that success, not the only success. A call that would ask, by elicitation or by sampling, returns an error and does not ask. A client that speaks 2025-11-25 still can: the server advertises that revision at initialize.

On `origin/main` (`038a856`), `rust-mcp-sdk` 0.9.0 re-exports `rust_mcp_schema::mcp_2025_11_25`, and that schema's `LATEST_PROTOCOL_VERSION` is `"2025-11-25"`. `src/bin/mcp_server/main.rs` sets the server's `protocol_version` from that constant (line 1280). A search of `src/bin/mcp_server` and `tests/` finds no test that asserts a protocol version or drives a JSON-RPC exchange of one.

Whose problem: the client that sends 2026-07-28, and the operator cutting a nab release that must answer it. No named product is the client; the release order is what makes it this release's problem. When: every request that carries that revision.

## Why now

The operator ordered this release to include the revision (2026-10-05, "go", after the release set was settled). Leaving it unsolved means a client that sends 2026-07-28 still does not get it.
